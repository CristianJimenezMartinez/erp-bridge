API-001 Path traversal (server.ts:117-122, 129-142). `req.params.filename` llega DECODIFICADO; `path.join(releasesDir,'latest',filename)` escapa del directorio y `res.sendFile(physicalPath)` lo sirve. El filtro anti-'..' de /releases (server.ts:147-152) va DESPUÉS y no aplica a esta ruta. VERIFICADO con express 4.22.2: GET /releases/latest/..%2F..%2F..%2Fapps%2Fapi%2Fpackage.json → filename="../../../apps/api/package.json". PoC: curl "https://bridge.cristianjm.com/releases/latest/..%2F..%2F..%2F..%2Fetc%2Fpasswd" (según send 0.19 el control de dotfiles es solo del último segmento: `.env` queda bloqueado pero dist/*.js, packages/**, ficheros bajo directorios con punto como .bentian-secrets/*.pem sí serían legibles — NO VERIFICADO en ejecución; impacto real depende de rutas del servidor). Fix:
```ts
const ALLOWED = new Set(['Bentian-Setup.exe','Bentian-Setup.zip','BentianAgent-Portable.zip','latest.json','manifest.json']);
app.get('/releases/latest/:filename', (req,res)=>{
  const filename = req.params.filename;
  if (!ALLOWED.has(filename) || filename !== path.basename(filename)) return res.status(404).end();
  const base = path.resolve(releasesDir);
  const target = path.resolve(base,'latest',filename);
  if (!target.startsWith(base + path.sep)) return res.status(403).end();
  return res.sendFile(target, { dotfiles:'deny' });
});
```
Aplicar la misma resolución segura a versionDir. Añadir test de regresión con %2e%2e%2f y %2F.
