# Informe bruto — Auditoría Agente (AGT-001…AGT-024)

# AUDITORÍA DE SEGURIDAD (solo lectura) — Agent Windows + packages (erp-bridge)
Todo verificado en código (file:line). Lo no comprobado va marcado "NO VERIFICADO". Rutas relativas a `erp-bridge/`. `[FROZEN]` = módulo sellado: solo mitigación por capa superior (adapter/middleware/decorator). Mitigaciones compatibles con AGENTS.md (puerto 39281 fijo, config en AppData, OpenFileDialog nativo, tray/CLI sin token).

## RESUMEN EJECUTIVO (top riesgos)
1. AGT-001 ALTA – Path traversal en nombre de fichero de actualización vía `version` del servidor → escritura de .exe arbitrario ANTES de verificar Ed25519 (persistencia en Startup).
2. AGT-002 ALTA – XSS en GUI (innerHTML sin escapar con datos remotos: JSON de la tienda, logs, Factusol) + sin CSP + API local sin auth ⇒ el JS inyectado lee secretos y controla el agente.
3. AGT-003 ALTA/MEDIA – API local sin autenticación, con GET con efectos secundarios sin exigir Origin ⇒ fuga NTLM por UNC (`currentPath`), DoS de diálogos, clickjacking.
4. AGT-004 ALTA/MEDIA – Secretos en claro en agent-config.json y expuestos por `GET /api/local/status` sin auth.
5. Resto MEDIA: SMTP sin TLS verificado, HTML injection en emails, bridge con secreto estático (sin HMAC/anti-replay desde el agente; `http://` permitido; secreto en URL), downgrade/sin isNewer, TOCTOU del auto-updater, licencia online sin prueba firmada, SSRF en test endpoints, licenseKey completa en diagnóstico.

## LO QUE SÍ ESTÁ BIEN
- Bind solo loopback; validación Host/Origin/Referer (anti DNS-rebinding y POST cross-site); puerto fijo sin port-hopping.
- `spawn`/`execFile` con arrays (sin shell); duplicado de comillas + truncado en SQL; transacciones BeginTrans/Rollback; cscript con datos por stdin.
