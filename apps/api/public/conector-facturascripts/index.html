Conector de FacturaScripts con tu tienda

FacturaScripts es un ERP de código abierto muy usado por autónomos y pequeñas empresas. Bentian lo conecta mediante su API REST v3, con una clave de acceso, sin acceder a su base de datos MySQL o PostgreSQL.

Estado: Beta, en validación con clientes piloto

El alta de pedidos usa el endpoint /api/3/crearPedidoCliente, cuya disponibilidad en cada versión de FacturaScripts aún no hemos confirmado; existe una alternativa con pedidoclientes y líneas que está pendiente de implementar. Si tu versión no lo ofrece, el catálogo y el stock sí pueden funcionar pero los pedidos no. Valida primero en un entorno de pruebas.

No ofrecemos garantías de sincronización en producción para este conector hasta completar la validación. Los conectores de Factusol y Sage 50 tienen su propia página de estado.

API REST v3

Cómo se conecta Bentian a FacturaScripts

La conexión es por HTTP o HTTPS contra la API REST v3 de tu instalación, autenticada con una clave API enviada en la cabecera Token.

  1. Activas la API REST en tu FacturaScripts y generas una clave de acceso desde su administración.
  2. En el agente indicas la URL base (por ejemplo http://127.0.0.1:8000) y pegas la clave API.
  3. El agente consulta productos, variantes y stocks por la API.
  4. Los pedidos de tu tienda se envían a la API como pedido de cliente con sus líneas.

Qué sincroniza el conector de FacturaScripts

1

Productos y variantes

Se combinan los productos (descripción y familia) con sus variantes (referencia, precio, coste y código de barras).

2

Stock por almacén

Disponible por referencia y almacén, a partir del recurso stocks de la API.

3

Pedidos de cliente

Serie, almacén, observaciones y líneas con referencia, cantidad, precio y descuento.

4

Modo Evaluación

Catálogo de ejemplo de informática y redes (SAI, switches, racks) para probar sin servidor.

Requisitos para FacturaScripts

  • • FacturaScripts con la API REST v3 activada y accesible por HTTP o HTTPS.
  • • Clave API con permisos sobre productos, stock y pedidos de cliente.
  • • Clientes creados previamente en FacturaScripts con su código de cliente.
  • • Windows 10, Windows 11 o Windows Server para el agente.

Requisitos generales del agente en Requisitos del sistema.

Puntos que seguimos validando en FacturaScripts

  • • El endpoint de creación de pedidos no está confirmado en todas las versiones.
  • • Si el pedido no trae un cliente válido, se usa un código genérico que puede no existir.
  • • Las consultas no están paginadas: en catálogos grandes pueden devolverse solo los primeros registros.
  • • Falta comprobar si el precio unitario de la API incluye o no el IVA.

Preguntas frecuentes sobre FacturaScripts y comercio electrónico

¿Dónde genero la clave API en FacturaScripts? ▼

En la administración de tu instalación, en la sección de la API REST. Cada instalación decide qué recursos expone a cada clave; asegúrate de incluir productos, variantes, stocks y pedidos de cliente.

¿Funciona con FacturaScripts alojado por un tercero? ▼

Sí, mientras la API sea accesible por HTTPS y tengas una clave. El agente solo necesita salida de red; no hay que abrir puertos en tu oficina. Si el alojamiento limita las peticiones, el conector puede recibir errores que hay que revisar.

¿Qué pasa si un producto tiene varias variantes? ▼

La API de variantes devuelve cada referencia por separado, pero el soporte de varias variantes por producto en la tienda aún no está completo. Es un caso importante para el piloto.

¿Se evita duplicar pedidos? ▼

No todavía. El alta de pedidos de FacturaScripts no consulta si ya existe uno con la misma referencia web. Es una de las correcciones prioritarias antes de recomendarlo en producción.

¿Puedo usarlo si mi FacturaScripts es local en el portátil del negocio? ▼

Sí: el agente se conecta a la URL local de la instalación (por ejemplo http://127.0.0.1:8000). La tienda recibirá los datos por la conexión saliente del agente, por lo que el equipo debe estar encendido para sincronizar.
