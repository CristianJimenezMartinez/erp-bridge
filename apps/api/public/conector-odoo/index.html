Conector de Odoo para tu tienda online

Bentian usa la API JSON-RPC de Odoo para leer productos y stock libre y para crear pedidos de venta. No toca la base de datos PostgreSQL de Odoo: todo pasa por los métodos oficiales del servidor.

Estado: Beta, en validación con clientes piloto

El flujo JSON-RPC está implementado y probado con el Modo Evaluación y con revisión de código, pero todavía no se ha validado en una instancia real de Odoo. No hemos contrastado el tratamiento de impuestos, unidades de medida ni multiempresa, así que no lo recomendamos aún para producción sin supervisión.

No ofrecemos garantías de sincronización en producción para este conector hasta completar la validación. Los conectores de Factusol y Sage 50 tienen su propia página de estado.

Cómo se conecta Bentian a Odoo

A diferencia de los conectores SQL, aquí la conexión es por HTTP o HTTPS contra tu servidor Odoo, con los datos de acceso de un usuario.

  1. Indicas la URL de tu Odoo (por ejemplo http://127.0.0.1:8069 o la de tu servidor), el nombre de la base de datos, el usuario y la contraseña.
  2. El agente se autentica con el método common.authenticate del endpoint /jsonrpc.
  3. El catálogo y el stock se leen con object.execute_kw y search_read; el pedido se crea con sale.order y sus líneas en una sola llamada.
  4. Si tu Odoo está en tu red local, el agente trabaja desde dentro; si está en la nube, basta con salida HTTPS.

Qué sincroniza el conector de Odoo

1

Productos

Variantes de producto con referencia interna (default_code), nombre, categoría, precio de venta, coste y código de barras.

2

Stock libre

Cantidad libre (free_qty) del producto, no la cantidad física total.

3

Clientes

Búsqueda del contacto por correo electrónico y alta de un nuevo res.partner si no existe.

4

Pedidos de venta

Pedido sale.order con líneas sale.order.line y referencia del pedido web en client_order_ref.

Requisitos para Odoo

  • • Odoo accesible por HTTP o HTTPS desde el equipo del agente (el adaptador está diseñado para las versiones 14 a 18, sin validar todavía en ninguna).
  • • Usuario de Odoo con permisos de lectura de productos y de creación de pedidos de venta; si tu versión lo admite, puede usarse una clave de API como contraseña.
  • • Módulos de Ventas e Inventario instalados.
  • • Los SKU de la tienda deben existir como referencia interna en Odoo.

Requisitos generales del agente en Requisitos del sistema.

Puntos que seguimos validando en Odoo

  • • Un pedido con un SKU que no existe en Odoo no se crea; el cliente puede haberse dado de alta antes.
  • • Impuestos, descuentos y unidad de medida de la línea no están mapeados todavía; revisa el precio con IVA.
  • • Las lecturas no están paginadas para catálogos muy grandes y el tiempo de espera es corto.
  • • El número que se devuelve al crear el pedido es el identificador interno, no el nombre tipo S00012.

Preguntas frecuentes sobre Odoo y comercio electrónico

¿Necesito instalar algún módulo en Odoo? ▼

No hay módulo de Bentian que instalar. El conector usa la API JSON-RPC que Odoo ya incluye en el servidor. Lo único necesario es que los productos tengan referencia interna y que el usuario tenga permisos suficientes.

¿Funciona con Odoo Online (SaaS) y Odoo.sh? ▼

Está pensado para cualquier URL que exponga /jsonrpc, así que en principio sí con HTTPS y credenciales válidas. Las instancias SaaS pueden limitar el acceso JSON-RPC según el plan; no lo hemos comprobado y es parte del piloto.

¿Se duplica el pedido si la tienda reintenta el envío? ▼

El conector busca primero un pedido con la misma referencia web (client_order_ref) y, si existe, lo devuelve en vez de crear otro. Esta comprobación no es atómica, así que dos envíos simultáneos podrían pasar a la vez.

¿Qué stock se envía a la web: físico, previsto o libre? ▼

Stock libre (free_qty), es decir, lo que se puede vender ahora. El perfil actual no filtra por almacén concreto ni por empresa; con varios almacenes u empresas hay que revisarlo.

¿Conecta directamente con la base de datos PostgreSQL? ▼

No. Aunque aparezca un perfil SQL en la configuración, no lo usamos para Odoo: la ruta correcta es JSON-RPC. Evitamos así escribir directamente en las tablas internas de Odoo.
