Conector de Visionwin para vender online

Visionwin se usa mucho en ferreterías y comercios de barrio. Bentian puede leer su base de datos tanto si corre en SQL Server Express como si está en un archivo .mdb local, y llevar artículos y pedidos hacia y desde tu tienda.

Estado: Beta, en validación con clientes piloto

Los esquemas de Visionwin (ARTICULOS, PEDIDOS_CLI, LINEAS_PEDIDOS_CLI) no están verificados contra una instalación real. Además, la versión SQL y la versión de archivo local no usan todavía exactamente los mismos nombres de columna, así que este conector necesita validación antes de usarlo en producción.

No ofrecemos garantías de sincronización en producción para este conector hasta completar la validación. Los conectores de Factusol y Sage 50 tienen su propia página de estado.

Cómo se conecta Bentian a Visionwin

Visionwin puede estar instalado con una base de datos de archivo o con SQL Server Express. El adaptador contempla las dos situaciones.

  1. Si tu Visionwin usa SQL Server Express, el agente se conecta a la instancia (por ejemplo .\SQLEXPRESS) con un usuario SQL.
  2. Si usa una base de datos de archivo .mdb, el agente la abre por OLEDB desde el equipo donde está la carpeta de datos, incluida una ruta de red compartida.
  3. Eliges la tarifa (PVP1, PVP2 o PVP3), el almacén y la serie de pedidos en el panel local.
  4. Los pedidos de tu tienda se escriben como pedidos de cliente de Visionwin.

Qué sincroniza el conector de Visionwin

1

Artículos

Código, nombre, familia, coste, código de barras y observaciones de los artículos que no están dados de baja.

2

Precios PVP1, PVP2 y PVP3

Las tres tarifas del artículo; el perfil publica PVP1 por defecto.

3

Stock

El stock del artículo. Hay más de un origen posible de stock en Visionwin y estamos validando cuál usar.

4

Pedidos de cliente

Cabecera y líneas de pedido con serie, número y observaciones.

Requisitos para Visionwin

  • • Visionwin con base de datos en SQL Server Express o en archivo .mdb.
  • • Para .mdb: el controlador OLEDB de Access (ACE) instalado en el equipo del agente y permiso de escritura en la carpeta de datos.
  • • Para SQL: usuario SQL con permisos de lectura y de escritura en pedidos.
  • • Windows 10, Windows 11 o Windows Server.

Requisitos generales del agente en Requisitos del sistema.

Puntos que seguimos validando en Visionwin

  • • Los nombres de columnas de pedidos difieren entre el perfil SQL y el modo archivo; se están unificando.
  • • El stock tiene varias fuentes posibles y la reserva al recibir un pedido no distingue almacenes.
  • • La detección de pedidos ya registrados se apoya en el texto de observaciones, que es un método débil.
  • • En modo archivo local, la numeración del pedido no está protegida frente a dos escrituras simultáneas.

Preguntas frecuentes sobre Visionwin y comercio electrónico

Mi Visionwin está en un archivo .mdb en el servidor. ¿Puedo usarlo? ▼

Es uno de los dos modos previstos. Se abre por OLEDB con el controlador de Access, igual que otros conectores de archivo de Bentian. En esta beta conviene trabajar sobre una copia, porque dos escrituras simultáneas a un .mdb compartido pueden dar problemas.

¿Qué tarifa se publica en la tienda? ▼

Visionwin guarda PVP1, PVP2 y PVP3 en el propio artículo. El perfil publica PVP1 por defecto; seleccionar otra tarifa desde el panel es una de las pruebas pendientes del piloto.

Soy ferretería con muchas referencias. ¿Aguanta el catálogo? ▼

No tenemos todavía una medición con un catálogo real de Visionwin. Las lecturas usan WITH (NOLOCK) en SQL, pero en modo archivo el rendimiento depende del disco y de la red. Por eso pedimos una copia para medir con tus datos.

¿Se pueden dar de baja artículos desde la web? ▼

No. El flujo actual lee el catálogo y escribe pedidos. Los artículos con BAJA marcada se excluyen del catálogo, pero la baja se gestiona siempre en Visionwin.

¿Cómo participo en el piloto de Visionwin? ▼

Escríbenos indicando si tu base de datos es SQL o .mdb y cuántas referencias tienes. Si puedes enviarnos la estructura de las tablas de pedidos (sin datos), acelera mucho la verificación del esquema.
