Conector de Business Central para tu e-commerce

Bentian se conecta a Business Central por su API OData v2.0 (cloud o servidor propio) o, en instalaciones on-premises y Dynamics NAV, directamente a SQL Server. Lee artículos y stock y crea pedidos de venta con sus líneas.

Estado: Beta, en validación con clientes piloto

La integración con Business Central no se ha validado todavía en un entorno real. El acceso por API usa autenticación básica o token Bearer, pero no incluye OAuth2 con Microsoft Entra ID, que es el método habitual en Business Central en la nube. Para el modo SQL tampoco hay validación del esquema real de tu empresa.

No ofrecemos garantías de sincronización en producción para este conector hasta completar la validación. Los conectores de Factusol y Sage 50 tienen su propia página de estado.

OData v4 / SQL

Cómo se conecta Bentian a Business Central

El adaptador decide la vía según el valor que pongas como servidor: una URL (OData) o una instancia SQL Server.

  1. Con una URL http o https, el agente usa la API v2.0 de Business Central, busca tu empresa en /companies y trabaja con items, salesOrders y salesOrderLines.
  2. La autenticación se hace con usuario y clave de servicio web en Basic, o con un token Bearer si lo introduces.
  3. Con una instancia SQL Server (on-premises o NAV), el agente detecta el prefijo de tablas de tu empresa y trabaja con Item, Item Ledger Entry, Sales Header y Sales Line.
  4. En ambos modos, el panel local del agente permite elegir serie y almacén.

Requisitos para Business Central

  • • Business Central con API v2.0 accesible o instancia SQL Server de Business Central/NAV.
  • • Usuario de servicio web con su clave de acceso, o un token Bearer válido.
  • • Cliente de venta predeterminado en Business Central para asignar los pedidos web.
  • • Windows 10, Windows 11 o Windows Server para el agente.

Requisitos generales del agente en Requisitos del sistema.

Puntos que seguimos validando en Business Central

  • • No hay autenticación OAuth2 con Microsoft Entra ID, necesaria en muchos entornos cloud.
  • • El cliente asignado al pedido está fijo en el perfil y debe ajustarse a tu configuración.
  • • En modo SQL, el pedido se escribe directamente en las tablas del ERP, algo que no es posible en la versión cloud.
  • • Las lecturas por API no siguen todavía los enlaces de paginación, por lo que un catálogo grande puede cortarse.

Preguntas frecuentes sobre Business Central y comercio electrónico

¿Funciona con Business Central SaaS? ▼

Parcialmente en teoría: la API OData v2.0 es la misma, pero SaaS exige OAuth2 con Microsoft Entra ID y Bentian todavía no lo incluye. Solo valdría con claves de servicio web o tokens Bearer que tu administrador haya habilitado.

¿Qué diferencia hay entre usar OData y SQL? ▼

OData usa la API oficial y es la vía recomendable porque respeta la lógica de negocio de Business Central. SQL se reserva a instalaciones on-premises o Dynamics NAV y escribe directamente en tablas, por lo que exige más cuidado.

¿Y si tengo varias empresas en el mismo Business Central? ▼

El conector busca la empresa por nombre y, si no la encuentra, puede tomar la primera de la lista. En entornos con varias empresas, revisa la configuración antes de crear pedidos de prueba.

¿Qué número de pedido recibe el pedido web? ▼

En la vía de API, el conector devuelve el número que Business Central asigna al crear el pedido; no lo hemos contrastado con tus series de numeración. En SQL, el conector calcula uno propio, fuera de la serie numérica del ERP, que es otro motivo para no usar SQL en producción sin pruebas.

¿Se puede probar con la empresa de demostración? ▼

Sí: el Modo Evaluación incluye un catálogo industrial de ejemplo y, en una instalación de pruebas con la empresa CRONUS, puedes comprobar lecturas y alta de pedido antes de pasar a tus datos reales.
